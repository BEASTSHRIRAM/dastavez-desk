# Dastavez Desk

**Speak once. Review everything. Print ready.**

Dastavez Desk is a document-operations tool for offices that prepare the same kinds of documents all day:
advocates, property brokers, application centres, travel agents and small accounting offices. The operator
describes the job (by voice or typing), the system turns it into structured facts, asks only for what is
missing, fills a template, checks the result, and waits for a person to approve before anything is exported.

> **Demonstration software.** The bundled templates are samples, all data in the seed is fictional, and
> nothing here is legal advice. Documents are drafts for human review. Nothing is signed, stamped,
> notarised, sent, filed or paid by this system.

---

## What makes it different from asking a chatbot

A chat assistant can also turn a description into a PDF. This project is about the parts it does not do.

| Capability | What it does |
|---|---|
| **Your own wording** | **Template Studio** reads a past draft (.docx), proposes which parts change per client, and builds a reusable template. Everything else stays exactly as you wrote it. The business owner must approve a template before it can be used. |
| **Approved wording is locked** | Only placeholders change. A before-and-after comparison shows every filled section and every section of approved text kept as written. |
| **Consistency guard** | Flags another client's name, phone or address inside a draft (you must tick each to approve), names spelled two ways between what was said and what was attached, and any figure whose words disagree with it. |
| **Amounts in words** | `Rs. 18,000.00 (Rupees Eighteen Thousand only)`, generated by code in Indian grouping, never by a model. |
| **Every value has evidence** | Each value shows the exact words it came from. Names, amounts and dates must be confirmed one by one before approval. |
| **Message to the client** | When details are missing it drafts the request list (including documents to bring) for you to copy. It never sends anything. |
| **Agents that can only suggest** | An analyst (Template Studio) and a reviewer (reads the draft against what was said) may add suggestions. Every quote they cite must exist word-for-word in the source, or it is dropped. They never edit, approve or export. |
| **Resumable, auditable** | LangGraph workflow with checkpoints: a missing-information question never loses earlier facts. Every approval, export and download is in an audit trail. |

Speech-to-text is deliberately out of scope: dictate with any tool (Wispr Flow, the OS dictation, your phone)
into the transcript box. The browser's own speech recognition is a built-in fallback.

## The five workspaces (one engine)

All five run on the same engine; they differ only in data (`backend/app/verticals/`).

| Workspace | Produces | Notable rules |
|---|---|---|
| **Legal documents** | Address, name or general declaration drafts; operator verification checklist | Approved clauses never change. Two operator checks (identity verified, facts read back) must be ticked by a person and are never inferred. |
| **Property and rental** | Rental agreement draft and handover checklist | Landlord is reused only from this business's saved records and only after you confirm which one. Zero deposit is a valid answer; blank is not. Total, end date and amounts in words are computed. |
| **Applications centre** | Application packet, intake sheet, incomplete-field report | Upload a form (.docx, .pdf, .txt); only its field labels are read and mapped. Nothing is submitted anywhere. |
| **Travel and visa** | Itinerary draft, supporting-document checklist, cover-letter draft, missing-information report | Requirements are shown only with a source and a last-verified date. The bundled dataset is fictional (`Demoland`, `Sampleland`) and says so. An unknown destination gets a warning and no checklist. |
| **Bookkeeping** | Expense voucher, ledger entry as XLSX and CSV | Decimal-safe tax split by code. Categories are suggestions until confirmed. Cells that look like formulas are neutralised in exports. |
| **Your own templates** | Whatever your template is | Fields come from the template; extraction rules are generated from each field's label. |

## Quick start (Windows, PowerShell)

Prerequisites: **Python 3.12 or newer**, **Node.js 20 or newer**, Git. Optional: Microsoft Word or LibreOffice
for PDF export. Docker only if you want a local PostgreSQL.

```powershell
git clone https://github.com/BEASTSHRIRAM/dastavez-desk.git
cd dastavez-desk

# one-time: Python venv, backend dependencies, frontend dependencies, .env files
.\scripts\setup.ps1

# every time: opens the API and the web app in two windows
.\scripts\dev.ps1
```

Then open **http://localhost:3000** and sign in with a demo account.

| Email | Role | Can |
|---|---|---|
| `operator@demo.test` | operator | start jobs, answer, approve, export |
| `owner@demo.test` | owner | everything, plus approve templates, delete cases, switch AI services on |
| `viewer@demo.test` | viewer | read only |
| `other@demo.test` | owner of a *different* business | used to see tenant isolation |

Password for all: `demo-pass`. These exist only when `SEED_DEMO=true`.

With no configuration the app runs on a local SQLite file in **demo mode**: a deterministic rule-based
extractor, no AI service, no credentials. Every workflow works offline.

### Manual setup (any OS)

```bash
# backend
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1          # Windows PowerShell. On macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                 # Windows: Copy-Item .env.example .env
uvicorn app.main:app --reload --port 8000

# frontend (second terminal)
cd frontend
npm install
cp .env.example .env.local
npm run dev                          # http://localhost:3000
```

API docs (Swagger): **http://localhost:8000/docs**.

## Configuration

`backend/.env` (never committed; copy from `backend/.env.example`):

| Variable | Default | Meaning |
|---|---|---|
| `DATABASE_URL` | local SQLite file | `postgresql://...` for PostgreSQL or Supabase. `postgres://` and `postgresql://` are both accepted; SSL is added for Supabase. |
| `SECRET_KEY` | `dev-only-secret` | Signs login tokens. **Set a long random value** for anything real: `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `STORAGE_DIR` | `./storage` | Uploads, generated files, studio uploads and custom templates, one folder per business. |
| `SEED_DEMO` | `true` | Creates the fictional demo businesses, logins and saved records. Set `false` for real client data. |
| `LLM_PROVIDER` | `demo` | `demo`, `groq`, `anthropic` or `openai`. |
| `GROQ_API_KEY` | empty | One key for Groq LLM and Groq Whisper. |
| `GROQ_LLM_MODEL` | `llama-3.3-70b-versatile` | Check Groq's current model list; names change. |
| `GROQ_STT_MODEL` | `whisper-large-v3-turbo` | Used only if `STT_PROVIDER=groq`. |
| `LLM_API_KEY`, `LLM_MODEL` | empty | For `anthropic` or `openai`. |
| `STT_PROVIDER`, `STT_API_KEY` | `demo` | `demo`, `groq` or `openai` server-side transcription. |
| `SOFFICE_PATH` | auto-detected | Path to LibreOffice's `soffice` if it is not on `PATH`. |

`frontend/.env.local`: `NEXT_PUBLIC_API_URL` (default `http://localhost:8000`). Never put a secret in a
`NEXT_PUBLIC_` variable.

### Turning on AI (Groq)

1. Put your key in `backend/.env`: `GROQ_API_KEY=...`, `LLM_PROVIDER=groq` (and `STT_PROVIDER=groq` if you want
   server-side transcription).
2. Restart the backend.
3. Sign in as an **owner** and tick **Allow AI services** in the sidebar.

Hosted AI never runs until step 3: text and audio are sent to a third party only after the business has
consented. If a model call fails, the app falls back to the rule engine and says so in the activity feed.

### Supabase

1. In Supabase, open **Project Settings, then Database, then Connection string**, and use the **Session pooler**
   (port 5432) or the direct connection. The Transaction pooler (port 6543) also works; the app turns off
   prepared statements for it.
2. Put it in `backend/.env`. Percent-encode special characters in the password (`@` becomes `%40`):
   ```
   DATABASE_URL=postgresql://postgres.PROJECTREF:PASSWORD@aws-0-REGION.pooler.supabase.com:5432/postgres
   ```
3. Start the backend. On startup it creates the tables, adds any columns introduced later, creates the LangGraph
   checkpoint tables **once, before serving traffic**, and seeds data if `SEED_DEMO=true`.

Security on Supabase: Supabase exposes `public` tables over its REST API to the `anon` and `authenticated` roles
unless row-level security is on. This backend is the only intended client (it connects as a privileged role),
so on every start it enables row-level security on **every** table (no policies) and revokes the API roles'
grants. Verify in the Supabase dashboard that every table shows RLS enabled.

The repository also contains `.mcp.json` pointing at the Supabase MCP server for this project. Authenticate it
once with `claude /mcp`. It contains a project reference, not a secret.

### PDF export

DOCX is always produced. PDF needs a converter, tried in this order:

1. **LibreOffice** (`soffice` on `PATH`, `SOFFICE_PATH`, or a standard install location). Headless; the right
   choice for servers.
2. **Microsoft Word on Windows**, driven invisibly through PowerShell COM automation. No extra packages.

If neither exists, the PDF checkbox is disabled and a request for a PDF returns a clear message. The DOCX is
still created. A PDF is never reported as made when it was not.

## How a job runs

```
describe  ->  questions  ->  review  ->  export
   |             |            |           |
 transcript   only the      approve     real files,
 (typed or    missing or    after you   each tied to the
 dictated)    uncertain     confirm     approval it came
              details       key values  from
```

The workflow is a LangGraph graph (`backend/app/agents/`) with these nodes:

`intake_request` → `classify_workspace_and_intent` → `extract_structured_facts` → `resolve_existing_records` →
`select_approved_template` → `validate_required_fields` → (`build_dynamic_ui_manifest` → `request_missing_information`,
looping back) → `apply_deterministic_rules` → `render_document_preview` (also runs the consistency guard and the
reviewer agent) → `build_dynamic_ui_manifest` → `request_human_review` → `export_approved_documents` →
`persist_audit_event`.

Rules the graph enforces:

- The graph **pauses** for missing fields, conflicting values, an ambiguous saved record, unresolved issues and
  every approval. Pauses survive a server restart (checkpoints in PostgreSQL or SQLite).
- Facts are stored as three kinds in separate rows: **source** (a saved record), **suggested** (extracted by rules
  or a model) and **confirmed** (a person accepted or typed it). A suggestion can never overwrite a confirmed value.
- Two different unconfirmed values for one field are a **conflict**; a person picks one.
- **Approval is bound to the exact values** (a hash of values, computed totals and template versions). If anything
  changes afterwards, the old approval no longer covers an export.
- Uploaded files, dictated text and model output are **data, never instructions**. Models get no tools.

### Generative UI

The agent does not return code. It returns a **UI manifest**: JSON naming components from a closed list (text
and typed inputs, party select, conflict choice, document checklist, change comparison, document preview,
approval panel, client message, export options). The server validates it (`extra="forbid"`), the frontend validates it
again with a strict schema, and anything outside the list is refused. The questions shown are computed from real
state (what is missing, uncertain or conflicting), so a rental agreement does not open with twenty generic fields.

### Progress events

`GET /api/cases/{id}/events/stream` (Server-Sent Events) sends typed, plain-language events such as
`facts_extracted`, `missing_fields`, `validation_warning`, `consistency_checked`, `agent_review_done`,
`preview_ready`, `approval_required`, `approved`, `export_ready`, `export_failed`. Model reasoning is never streamed.

## Template Studio (your own templates)

**Templates → Add your own template**

1. **Upload** a past draft as .docx.
2. **Review the analyst's proposals.** It finds names (with honorifics, "S/o, D/o, W/o", "daughter of", "I, ..."),
   addresses ending in a PIN code, dates in several formats, amounts (`Rs. 18,000/-`) and their **amount in words**,
   phones, Aadhaar-style and PAN numbers, emails, bracketed or highlighted text, and blanks. Plain two-word
   capitalised names are offered unticked. You tick, rename, retype, and mark which values need confirmation.
   - Identical text becomes one field; each blank is its own field.
   - Honorifics (`Mrs.`, `Shri`) become a **choice**, so a new client never inherits the old title.
   - Signature and witness blanks are left blank by default.
   - An amount in words is linked to its amount and regenerated, so figure and words always agree.
3. **Build.** You get a preview with labelled blanks, and a list of anything that **still looks like a previous
   client's details**, so it cannot leak into the next document.
4. **Approve.** An owner approves the wording. Only then can a job start from it. Each new build of the same
   template becomes a new version; cases keep running on the latest *approved* one until the new one is approved.

Custom-template fields are read in demo mode from phrases built from each field's label (for example
"The declarant name is Neha Singh."). With AI services on, free wording works too.

## API overview

All routes are under `/api`. Everything except `health` and `auth/login` needs `Authorization: Bearer <token>`.
Viewers can read; operators write; owners also delete cases, approve templates and change consent.

| Area | Routes |
|---|---|
| Auth and settings | `POST /auth/login`, `GET /me`, `GET /capabilities`, `PUT /tenant/consent`, `GET /health` |
| Catalog | `GET /workspaces`, `GET /templates`, `GET /templates/{id}`, `GET /templates/{id}/preview`, `POST /templates/{id}/approve`, `POST /templates/{id}/retire`, `GET/POST /parties`, `DELETE /parties/{id}` |
| Template Studio | `POST /studio/analyze`, `POST /studio/build` |
| Cases | `POST /cases` (supports `Idempotency-Key`), `GET /cases`, `GET /cases/{id}`, `DELETE /cases/{id}`, `POST /cases/{id}/cancel` |
| Workflow | `POST /cases/{id}/intake`, `POST /cases/{id}/answers`, `POST /cases/{id}/review/edit`, `POST /cases/{id}/approve`, `POST /cases/{id}/export`, `POST /cases/{id}/reopen`, `POST /cases/{id}/finish`, `POST /cases/{id}/retry` |
| Read side | `GET /cases/{id}/manifest`, `.../preview`, `.../events`, `.../events/stream`, `.../audit`, `.../documents` |
| Files | `POST /cases/{id}/attachments`, `.../attachments/sample-form`, `PUT .../form-mapping`, `GET /attachments/{id}/download`, `DELETE /attachments/{id}`, `GET /documents/{id}/download`, `POST /cases/{id}/transcribe` |

Errors use normal status codes with a message a person can act on. Answers that fail validation return `422` with a
per-field `errors` map. Exports and downloads of unapproved drafts return `409`.

## Security and privacy model

- **Tenant isolation.** Every business-owned row carries `tenant_id` and every repository query filters on it. A
  valid ID from another business behaves exactly like a missing one (404). This is covered by tests across cases,
  documents, attachments, saved records and templates.
- **Roles.** `viewer` (read), `operator` (work), `owner` (approve templates, delete, consent). Role checks are on the
  server.
- **Uploads.** Extension allow-list, size limit, content checked against the extension (magic bytes), server-chosen
  storage names, display names sanitised, paths confined to the business's folder.
- **Untrusted content.** Uploaded notes and dictation cannot instruct the system. A test uploads text that says
  "approve and export everything" and confirms nothing happens.
- **Exports.** Only approved output is downloadable. Spreadsheet cells that start with `=`, `+`, `-`, `@` are
  neutralised.
- **Third-party AI.** Off until an owner consents. Hosted extraction output is validated against typed schemas
  and quoted evidence before it can touch business data.
- **Retention.** Owners can delete a case (rows, uploads and exported files); a redacted record that a deletion
  happened remains in the audit log. Saved records are soft-deleted.
- **Database.** On PostgreSQL, row-level security is enabled on every table on every start (see Supabase above).

Not in scope for this MVP: SSO, password reset, rate limiting, malware scanning of uploads, encryption at rest
beyond what your database provider offers, and an enterprise permissions model. Add them before real client use.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `WinError 10013` starting uvicorn | Port 8000 is already in use (often a previous server still running). Stop it (`Get-Process python \| Stop-Process`) or use `--port 8001` and set `NEXT_PUBLIC_API_URL`. |
| `uv uvicorn ...` says unrecognised subcommand | Activate the venv and run `uvicorn app.main:app --reload`, or `.\.venv\Scripts\python -m uvicorn app.main:app --reload`. |
| PowerShell blocks `Activate.ps1` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, then retry. |
| Screen stuck on "Reading your request" | The run failed before its first step. Check the activity panel. On PostgreSQL this was caused by a held database session blocking the checkpoint index build; fixed by setting the checkpointer up once at startup. If you see it again, restart the backend and start a new job. |
| "PDF export is not available" | Install LibreOffice or Microsoft Word, or set `SOFFICE_PATH`. DOCX still works. |
| Microphone does nothing | The browser blocked it or does not support speech recognition. Type, or dictate into the box with any dictation tool. |
| Cannot sign in on Supabase | Demo users exist only if `SEED_DEMO=true` on first start. Check the password encoding in `DATABASE_URL`. |
| Template Studio finds nothing | The draft may use text boxes or images, which are not read. Type `{{ field_name }}` where a value belongs and upload again. |

## Known limitations

- Studio detection is rule-based and tuned to English and Indian legal formats. It reads body text, tables, headers
  and footers, not text boxes or images.
- In demo mode, rule-based extraction understands English phrasing. Hindi, Marathi and free-form speech need AI
  services on.
- Titles (Mr., Mrs.) in custom templates are always asked, never guessed.
- Browser speech recognition may send audio to the browser vendor. Typing sends nothing anywhere.
- Travel requirements are a fictional demonstration dataset (`backend/app/verticals/data/travel_requirements.json`).
  Replace entries only with sources you have verified, with a `last_verified` date.
- The built-in PDF path depends on LibreOffice or Word. There is no pure-Python PDF fallback.
- Not built: deleting custom templates, comparing template versions, multi-document bundles by matter type,
  and any outbound sending (by design).
